# Как это устроено

[English version](how-it-works.md)

## Окна

Underlay находит два окна: то, в котором живёт вызывающий, и host-окно под ним.

| Откуда вызвано | Своё окно | Host-окно | Лучший источник |
|----------------|-----------|-----------|-----------------|
| `Dialog`, `AlertDialog` из Material 3 | окно диалога | окно активити | `SystemBlur` |
| `Popup`, `PopupWindow`, `DropdownMenu` | корневая View через `WindowManager` | окно активити | `SystemBlur` |
| `ModalBottomSheet` | своё окно | окно активити | `SystemBlur` |
| View-`Dialog`, `DialogFragment`, `BottomSheetDialog` | окно диалога | окно активити | `SystemBlur` |
| Прозрачная или плавающая активити | окно активити | нет, окно под ней принадлежит другой активити | `SystemBlur` |
| Оверлей внутри окна активити | нет | нет | `Fallback` |

Без своего окна host-окном оказалось бы окно самого вызывающего, и снимок запёк бы оверлей в его же
подложку. Этот случай рисует `fallback`; для него есть библиотеки размытия внутри окна.

У прозрачной активити host-окна тоже нет, поэтому она падает из `SystemBlur` сразу в `Fallback`.

## Системное размытие

`FLAG_BLUR_BEHIND` и `blurBehindRadius` ставятся на окно оверлея: через `Window.setAttributes` для
Compose-`Dialog` и через `WindowManager.updateViewLayout` для всего остального. Система размывает всё за окном,
вживую и бесплатно для приложения.

Межоконное размытие бывает выключено: его выключает энергосбережение, а некоторые производители не
включают вовсе. Underlay слушает `WindowManager.addCrossWindowBlurEnabledListener`, снимает флаг и
переходит на снимок. Так же он поступает, если окно флаг не приняло.

## Снимок

Host-окно копируется через `PixelCopy` начиная с API 26, ниже — через `decorView.draw()`. На API 26+
`draw()` запасным вариантом не служит: он падает на hardware bitmap, а Coil и Glide декодируют в них
по умолчанию.

Захват ждёт, пока будет нарисован кадр, в котором его попросили, берёт наибольшую точную четверть
окна и размывается через `RenderEffect` на GPU начиная с API 31, ниже — тремя box-проходами на
`Dispatchers.Default`. Пока снимка нет, рисуется только тинт, а первый снимок проявляется за 200 мс.

`blurRadius` — тот же радиус, что принимают `Modifier.blur`, `blurBehindRadius` и
`RenderEffect.createBlurEffect`, в пикселях окна. Платформа переводит его в сигму гауссианы как
`0.57735 * radius + 0.5`, и снимок использует ту же сигму в своей четверти масштаба, поэтому все
три пути размывают одинаково. На CPU сигма становится радиусом бокса, три прохода которого дают
ближайшую сигму: `(sqrt(4*sigma^2 + 1) - 1) / 2` с округлением к ближайшему соседу. Box-проходы
усредняют премультиплицированные каналы, поэтому прозрачный сосед не протекает своим цветом.

Host-окно с `FLAG_SECURE` снимается только в окно оверлея, которое тоже защищено; Compose-`Dialog`
и `Popup` защищены по умолчанию. Иначе снимок пропускается, а снимок, сделанный до того, как host
стал защищённым, убирается.

## Компромиссы

- **Снимок заморожен, пока его не попросят следовать.** Движение под ним подхватывается по
  `refresh()` или с отставанием в пару кадров с `liveSnapshot`. Неудачный перезахват оставляет
  снимок на экране, кроме случая, когда host-окно сменило размер и старый кадр больше не совпадает.
- **`FLAG_BLUR_BEHIND` — флаг окна.** `SystemBlur` размывает всё за окном оверлея, `Snapshot` —
  только то, что под композаблом. Вешайте модификатор один раз на окно, на композабл во всё окно,
  чтобы оба источника давали одну картинку.
- **Host — всегда окно активити.** При диалоге поверх диалога снимок захватывает активити, а не
  промежуточный диалог.

## Границы

Kotlin Multiplatform не планируется. На iOS Compose рисует диалоги в той же иерархии, а размытие
закрывает `UIVisualEffectView`. У десктопа граница есть, но нет ничего похожего на
`FLAG_BLUR_BEHIND` и `PixelCopy`; переносим был бы только box-блюр.
