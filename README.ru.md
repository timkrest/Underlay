# Underlay

[![CI](https://github.com/timkrest/Underlay/actions/workflows/ci.yml/badge.svg)](https://github.com/timkrest/Underlay/actions/workflows/ci.yml)

[English](README.md)

Размытая подложка для диалогов и оверлеев, живущих **в собственном окне**, начиная с API 24.

| `Snapshot` под `Dialog` | `Fallback` в прозрачной активити |
|---|---|
| <img src="docs/snapshot.png" width="300" alt="Диалог поверх сетки плиток, подложка размыта по снимку окна активити"> | <img src="docs/fallback.png" width="300" alt="Прозрачная активити рисует сплошной цвет: захватывать нечего"> |

Оба кадра — из `:sample` на одном устройстве. Бейдж называет достигнутый шаг.

```kotlin
Dialog(onDismissRequest = ::dismiss) {
    Box(
        modifier = Modifier
            .fillMaxSize()
            .blurredUnderlay(
                blurRadius = 16.dp,
                tint = Color.Black.copy(alpha = 0.3f),
                fallback = MaterialTheme.colorScheme.surface,
            ),
    ) {
        // содержимое диалога
    }
}
```

## Зачем это нужно

Compose-библиотеки размытия — [haze](https://github.com/chrisbanes/haze),
[Cloudy](https://github.com/skydoves/Cloudy), [imla](https://github.com/desugar-64/imla) — размывают
поддерево композиции, которое им видно: помечаешь источник модификатором, они снимают его в
`GraphicsLayer` и размывают этот слой.

`Dialog` в это поддерево не входит. Он рисуется в **отдельном окне**, а содержимое за ним
принадлежит окну активити — другому дереву render node целиком. Никакая пометка источника через эту
границу не дотянется. Пробел в платформе отслеживается апстримом:
[Support window blur in compose dialogs](https://issuetracker.google.com/issues/296272625).

Underlay закрывает этот пробел и только его. Для живого размытия содержимого внутри своего окна
берите haze или Cloudy — они прекрасно совмещаются: Underlay даёт подложку, haze — живой эффект
поверх.

## Как деградирует

Три шага, побеждает лучший доступный:

| Шаг | Требует | Что происходит |
|------|----------|--------------|
| `SystemBlur` | API 31+, своё окно | `FLAG_BLUR_BEHIND` + `blurBehindRadius`. Живое, на GPU, бесплатно. Сверху рисуется только тинт. |
| `Snapshot` | API 24+, достижимое host-окно | Один `PixelCopy` host-окна (`decorView.draw()` ниже API 26), уменьшение ×4, box-размытие на `Dispatchers.Default`. |
| `Fallback` | — | Сплошной цвет `fallback`. |

Захват проходит через границу кадра, `PixelCopy` и фоновое размытие. Пока он идёт, модификатор
сообщает `Pending` и рисует только тинт: оверлей проявляется из неразмытого содержимого host-окна в
размытый снимок, а не мигает непрозрачным `fallback` посередине.

Шаг 1 — не разовая проверка. Система молча выключает межоконное размытие в режиме энергосбережения,
поэтому Underlay подписывается на `WindowManager.addCrossWindowBlurEnabledListener`, снимает флаг
окна и проваливается на снимок, когда это происходит.

Путь снимка обходит hardware bitmaps. `decorView.draw()` в программный canvas бросает
`Software rendering doesn't support hardware bitmaps`, как только что-нибудь на экране декодировано
загрузчиком картинок в hardware bitmap, — а на API 26+ это поведение Coil и Glide по умолчанию.
Отсюда `PixelCopy` везде, где он есть.

## Окна

Underlay резолвит два окна по отдельности: то, в котором живёт вызывающий, и host-окно под ним.
Оба должны сойтись, иначе размывать нечего.

| Откуда вызвано | Своё окно | Host-окно | Лучший шаг |
|-------------|------------|-------------|-----------|
| `Dialog` | окно диалога | окно активити | `SystemBlur` |
| `Popup`, `PopupWindow` | корневая View через `WindowManager` | окно активити | `SystemBlur` |
| Прозрачная или плавающая активити | окно активити | нет — принадлежит другой задаче | `SystemBlur` |
| Обычный оверлей внутри активити | нет | нет | `Fallback` |

Последней строке рисовать нечего: без своего окна host-окном оказывается собственное окно
вызывающего, и захват свернул бы оверлей в его же подложку. Underlay рисует `fallback`.

## Отчёт о текущем шаге

```kotlin
Modifier.blurredUnderlay(
    blurRadius = 16.dp,
    tint = Color.Black.copy(alpha = 0.3f),
    fallback = MaterialTheme.colorScheme.surface,
    onSourceChange = { source -> Log.d("underlay", "step: $source") },
)
```

`UnderlaySource` — это `SystemBlur`, `Snapshot`, `Pending` или `Fallback`. Колбэк срабатывает на
каждое изменение, включая провал вниз, когда система выключает межоконное размытие.

## Установка

```kotlin
dependencies {
    implementation("com.timkrest:underlay:0.1.0")
}
```

`minSdk 24`, байткод Java 11. Зависимости: Compose runtime и UI (отданы через `api`),
`activity-compose`, `core-ktx`, `annotation` и `kotlinx-coroutines-core`.

## О чём стоит знать

- **Снимок заморожен.** Он захватывает host-окно один раз и ещё раз, когда это окно меняет размер
  или конфигурацию. Движение под ним не отражается. Для модального оверлея это ровно то, что нужно;
  для всплывашки над прокручивающимся списком берите библиотеку, работающую внутри окна. Неудавшийся
  перезахват оставляет снимок, уже нарисованный на экране, вместо падения в `fallback` — кроме
  случая, когда host сменил размер: тогда старый кадр больше не совпадает, и до успешного захвата
  рисуется `fallback`.
- **`FLAG_BLUR_BEHIND` — флаг окна.** Шаг 1 размывает всё за окном оверлея целиком, шаг 2 — только
  то, что за композаблом. Вешайте модификатор на композабл, заполняющий окно оверлея, чтобы оба шага
  давали одну картинку.
- **`blurRadius` — это сигма гауссианы**, тот же смысл, что у Figma и `RenderEffect.createBlurEffect`.
  Снимок переводит её в радиус box-размытия по трёхпроходной аппроксимации из спецификации
  SVG-фильтров, `box size = sigma * 3 * sqrt(2*pi) / 4`, уже на уменьшенном ×4 кадре.
- **Host — всегда окно активити.** При наложенных друг на друга оверлеях (диалог поверх диалога) шаг
  2 снимает активити, а не промежуточный диалог; у шага 1 этого шва нет.

## Сэмпл

`:sample` открывает по оверлею на каждый вид окна — Compose `Dialog`, Compose `Popup`, прозрачная
активити, обычный оверлей внутри окна — поверх сетки hardware bitmaps, показывает активный шаг и даёт
таскать радиус. При активном `SystemBlur` подсказывает про энергосбережение — это способ увидеть
провал в `Snapshot` на живом устройстве.

```bash
./gradlew :sample:installDebug
```

## Границы

Kotlin Multiplatform не планируется. Пробел, ради которого библиотека существует, — андроидный: в
Compose на iOS диалоги рисуются в той же иерархии View, границы окна там нет, а размытие уже закрыто
`UIVisualEffectView`. У десктопа граница есть, но общего с `FLAG_BLUR_BEHIND` и `PixelCopy` — ничего;
это была бы вторая реализация, а не общий код. Переносимо здесь только box-размытие.
